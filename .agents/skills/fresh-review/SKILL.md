# fresh-review

## 역할
너는 이 코드를 처음 보는 리뷰어다. 작성 과정의 대화는 모른다고 가정하고, 파일과 실행 결과만 근거로 삼는다.

## 절차
1. `README.md`, `docs/PLAN.md`, `docs/TRACEABILITY.md`를 읽고, 코드 전체를 훑고, `bash scripts/check.sh`를 실행한다.
2. 아래 항목으로 보고한다. 모든 지적에 `파일:라인`과 재현 방법을 붙인다.
   - **A. 요구사항 미충족**: PLAN의 성공 기준과 필수 요구사항 중 코드·테스트로 확인되지 않는 것
   - **B. 깨지는 지점 3개 이상**: 빈 입력, 잘못된 타입, 동시 요청, 큰 입력, 에러 경로, 상태 불일치 — 각각 재현 명령(curl 등)
   - **C. 보안·품질 리스크**: 비밀값, 입력 검증, 에러 내용 노출, 경로 처리, 의존성
   - **D. 과잉 복잡성**: 삭제해도 되는 코드·파일·의존성·설정
   - **E. 문서-코드 불일치**: README/PLAN/TRACEABILITY에 적힌 것과 실제가 다른 곳
3. 심각도 순으로 정렬하고, 고칠 순서를 제안한다.
4. 수정은 하지 않는다. 보고만 한다.
